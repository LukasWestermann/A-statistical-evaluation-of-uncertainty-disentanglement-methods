# Paper tables — data provenance and conventions

Generated by `scripts/make_paper_tables.py --out tables/`. Regenerate any time raw
results change — nothing here is hand-edited or transcribed.

There are two families of output, both from the same script/run:
- **The 6 original tables** (`tab_ood.tex`, `tab_undersampling.tex`,
  `tab_samplesize.tex`, `tab_noise.tex`, `tab_ovb.tex`, `tab_ovb_rho.tex`) — AU/EU
  min-max normalised per model, described throughout the rest of this file.
- **9 companion tables** (`tab_*_absolute.tex`, `tab_*_autruth.tex`,
  `tab_noise_au_sweep_corr.tex`, OOD/Undersampling/Sample-size/Noise-level only, no
  OVB companions) — absolute-scale AU/EU summaries and AU-vs-true-noise-variance
  diagnostics, documented in its own section below. The two families are
  independent code paths in the script; generating one never changes the other
  (verified: regenerating the 6 originals with the same `--models` reproduces them
  byte-for-byte after the companion code was added).

Scope: variance-based decomposition only (AU/EU/ρ), 4 DGPs (Lin-Hom, Lin-Het,
Sin-Hom, Sin-Het), thesis ordering preserved throughout. **Which models are
included is chosen per run via `--models`** (comma-separated npz tags, any subset/
order of `Deep_Ensemble,MC_Dropout,BNN,BAMLSS`) — default is `Deep_Ensemble,BAMLSS`
if omitted, matching the original scope. A model with no saved data for a given
cell always renders as `---`, never an error. The tables currently checked in here
were generated with the default (`Deep_Ensemble,BAMLSS`); run with a different
`--models` value to regenerate for a different model set.

As of the last run: MC Dropout has real data for OOD (all 4 DGPs) and Sample-size
(all 4 DGPs x 5 shares) — both generated after the original data audit found zero
MC Dropout files anywhere, so that audit note is stale for these two experiments
specifically — but still none for Undersampling/Noise-level/OVB. BNN has real data
only for OOD/Lin-Hom (1 file) and none elsewhere. Including either in `--models` is
fully supported; expect `---` outside the experiments noted above until more runs
exist. Sweep tables (`tab_samplesize.tex`, `tab_noise.tex`, `tab_ovb.tex`,
`tab_ovb_rho.tex`) grow by 3 columns per model and print a console `WARNING` (see
`estimate_sweep_table_width_pt` in the script) when the estimated width exceeds the
NeurIPS single-column budget — this happens at 4 models (13 columns, ~500pt vs.
~396pt budget); 2–3 models fit comfortably.

**`tab_samplesize.tex` was originally deferred** — at first audit, BAMLSS had zero
saved results for the sample-size sweep (0/20 cells). That gap has since closed
(BAMLSS and, separately, MC Dropout both now have complete 20/20 sample-size data —
this was re-checked directly against disk before generating the table below, not
assumed from the original audit) — so the table is now generated like the rest.
BNN still has 0/20 for sample-size, and shows `---` throughout if included via
`--models`.

## Data sources

| Table | Source path pattern |
|---|---|
| `tab_ood.tex` | `results/ood/outputs/ood/<noise>/<func>/*<Model>*raw_outputs*.npz` |
| `tab_undersampling.tex` | `results/undersampling/outputs/undersampling/<noise>/<func>/*<Model>*raw_outputs*.npz` |
| `tab_samplesize.tex` | `results/sample_size/outputs/sample_size/<noise>/<func>/*<Model>*pct<pct>*raw_outputs*.npz` |
| `tab_noise.tex` | `results/noise_level/outputs/noise_level/<noise>/<func>/normal/*<Model>*tau<τ>*raw_outputs*.npz` |
| `tab_ovb.tex`, `tab_ovb_rho.tex` | `results/ovb/{deep_ensemble,bamlss}/<noise>/<func>/ovb_outputs_<Model>_*.npz` |

Every value is recomputed from raw per-grid-point `mu_samples`/`sigma2_samples`
(never from a pre-aggregated Excel/summary file): `AU(x) = mean(sigma2_samples(x),
axis=members)`, `EU(x) = var(mu_samples(x), axis=members)`. Where a cell has more
than one dated file (re-runs on different days, not independent seeds — see below),
the latest date is used. File-resolution helpers (`resolve_latest_npz`,
`resolve_latest_npz_at_pct`, `resolve_latest_npz_at_tau`, `build_ood_mask`,
`ensure_samples_first`) are reused from `utils/knn_entropy_regression.py` rather
than reimplemented.

## Normalisation scope per table (pool first, then aggregate — see script docstring)

- **OOD / Undersampling**: pooled scope = the one saved grid per (model, DGP)
  (already spans both regions). Min-max normalise AU and EU separately over that
  whole grid, then take the region mean.
- **Sample-size / Noise-level / OVB (all sweeps)**: pooled scope = every swept knob
  value's own grid, concatenated, per (model, DGP) — but only over knob values that
  actually have data (a missing knob value is excluded from the pool, not
  padded/imputed). Normalise over the pool, then take the per-knob mean.
- ρ(AU, EU) is Pearson correlation on the **raw** (non-normalised) values within
  each region/knob subset — normalisation is monotone-affine and doesn't change ρ.

## Region/knob definitions used

- **OOD**: ID = `x ∈ [-5, 10)`, OOD = `x ∈ [10, 15]` — matches the repo-wide
  `train_range=(-5,10)`/OOD-extrapolation-`(10,15)` convention already hardcoded as
  `OOD_RANGES`/`DEFAULT_OOD_RANGES` in `scripts/plot_ood_4x2_au_eu_all_conditions.py`
  and `utils/knn_entropy_regression.py`.
- **Undersampling**: under-sampled = `x ∈ (0, 6)` (density factor 0.01), well-sampled
  = `x ∈ [-5,0] ∪ [6,10]` (density factor 1). **This is not stored in any npz** and
  required real detective work: `utils/undersampling_experiments.py`'s in-code
  default (`[((-5,0),0.2),((0,5),1.0),((5,10),0.2)]`) is dead code, never actually
  used for the saved runs, and `scripts/export_undersampling_overview_latex.py`'s
  `DEFAULT_SAMPLING_REGIONS` comment claims `[((-5,4),1.0),((4,8),0.05),((8,10),1.0)]`
  — **also does not match the data on disk**. The region tuple actually used here,
  `[((-5,0),1.0), ((0,6),0.01), ((6,10),1.0)]`, was determined by counting real
  `x_train_subset` points per candidate region in every saved npz and checking which
  candidate's predicted proportional-density point split matches the observed
  counts (551/6/441 out of 998) — it matches to within rounding; the `(4,8)`-based
  candidate does not (predicted ~18 points in the sparse band, actual 216). If you
  have the actual notebook parameter cell that generated these files, please
  double-check against it — this was reconstructed, not read from authoritative
  metadata.
- **OVB tables use the "omitted" (X-only) model output**, not the "full" (X+Z)
  model — `save_ovb_model_outputs` saves both (`mu_samples`/`sigma2_samples` for
  omitted, `mu_samples_full`/`sigma2_samples_full` for full); this script only ever
  reads the default (omitted) keys. This matches the experiment's name and is the
  only interpretation consistent with a mis-specification effect (the full model,
  having access to Z, wouldn't show growing bias-driven AU as β2 increases). Not
  explicitly stated in the original task, flagging in case a different choice was
  intended.

## Seed handling

All 5 experiments now support an optional seed-replicate dimension
(`save_model_outputs`/`save_ovb_model_outputs` both take a `seed` parameter, folded
into the filename as a `seed{N}` token and into npz metadata). Where multiple
seed-replicate files exist for a cell, every table here **pools** the raw AU/EU
arrays across all found seeds (via `load_ale_epi_pooled_across_seeds`) before
normalizing/aggregating — this is a single pooled point estimate, not a
mean ± sd across seeds. As of this writing no experiment has seed-tagged data on
disk yet (the seed loops were added to the notebooks but not run), so every table
here still reflects the original single-run-per-cell behavior — confirmed via a
full regression check (every table byte-identical before/after the seed-pooling
code was added). If you want to directly check run-to-run variability rather than
a pooled estimate, see `compute_samplesize_seed_spread` in
`scripts/make_paper_tables.py` (sample-size only for now), which reports each
seed's value independently rather than pooling them.

Some cells have duplicate-dated files from re-running the pipeline (OOD: 2 dates
per cell; Noise-level Deep Ensemble: 2 dates per cell, confirmed byte-identical on
3 spot-checked pairs) — these are literal re-saves, not independent replicates,
and are deduplicated by taking the latest date within each seed (or within the
no-seed group, for cells with no seed-tagged files).

## Missing combinations (rendered as `---`)

- **`tab_noise.tex`**: BAMLSS at τ ∈ {1, 2, 2.5} for all 4 DGPs (12 cells) — only
  τ ∈ {0.5, 5} has BAMLSS data. Deep Ensemble has all 5 τ values for every DGP.
- **`tab_ood.tex`, `tab_undersampling.tex`, `tab_samplesize.tex`, `tab_ovb.tex`,
  `tab_ovb_rho.tex`**: no missing cells at the default `Deep_Ensemble,BAMLSS` scope —
  full data coverage for both models across all 4 DGPs. (Note: `tab_ovb.tex`'s
  BAMLSS/sin-heteroscedastic β2 ∈ {1.0, 2.0} points, and *all* of `tab_samplesize.tex`'s
  BAMLSS column, were *missing* when this repo was first audited earlier in this
  session — both gaps closed from background runs finishing before the table script
  was actually (re-)run. Re-run the script if you suspect any experiment is still in
  progress, to pick up newly-completed data.)
- If you add MC Dropout or BNN via `--models`, expect them to be entirely or mostly
  `---` outside OOD (MC Dropout: real data only for OOD + Sample-size currently;
  BNN: real data only for OOD/Lin-Hom, one file) — see the model-scope note above.

## Two other things worth knowing about the raw data (non-blocking, just noted)

- The `percentages`/`tau_values` *default* parameters in
  `utils/sample_size_experiments.py`/`utils/noise_level_experiments.py` include
  15% and τ=10 respectively, but **no data for either value exists on disk for any
  model** — the sweeps actually run used a narrower grid than those defaults
  suggest. Doesn't affect these tables (5/10/25/50/100% and the τ set used here
  match what's really on disk), just flagging so it isn't mistaken for a bug.
- `distribution='laplace'` is fully wired in the noise-level code but **zero
  Laplace data was ever generated** for either model — `tab_noise.tex` only ever
  used `distribution=normal` since no distribution axis was requested.

## Formatting

`booktabs` only (no vertical rules), `\small` + `\tabcolsep=4pt`, values to 4
decimals, `\multicolumn{N}{l}{\textit{...}}` scenario headers with `\addlinespace`
between blocks, plain `r` columns (no `siunitx` — not currently a dependency
anywhere else in this repo). All 6 tables have at most 7 columns at the default
2-model scope; a character-width
estimate puts the widest table at roughly 300pt of the ~396pt (5.5in) NeurIPS
single-column budget at `\small` — comfortable margin. This is a heuristic
estimate, not a compiled check: no LaTeX toolchain (`pdflatex`/`xelatex`) is
installed in this environment, so please do a real compile/visual check in
Overleaf before submitting.

## Companion tables: absolute-scale + AU-vs-truth diagnostics

Same raw `mu_samples`/`sigma2_samples` source, same region/knob definitions, same
`--models` scope as the corresponding original table, same row order/DGP headings/
`\addlinespace` separators (read a companion against its original by row position).
Variance-based decomposition only, OOD/Undersampling/Sample-size/Noise-level only
(no OVB companions). Values are **raw** (never min-max normalised).

- `tab_ood_absolute.tex` / `tab_undersampling_absolute.tex` / `tab_samplesize_absolute.tex`
  / `tab_noise_absolute.tex` — per region/knob: `$mean \pm sd$` (population, ddof=0)
  for AU and EU, $\rho$(AU,EU), and the epistemic share, in that column order
  (mirrors the original tables' AU, EU, $\rho$ ordering, with Share appended as
  the new addition). $\rho$(AU,EU) is the exact same quantity already in the
  original (normalised) tables' $\rho$ column — same `_rho()` call on the same raw
  arrays, numerically identical (min-max normalisation doesn't change Pearson r) —
  surfaced here too so it doesn't require cross-referencing the other table. Share
  is computed **pointwise then averaged** (`mean_x[EU(x)/(AU(x)+EU(x))]`), not
  `mean(EU)/(mean(AU)+mean(EU))` — the two differ whenever the ratio varies across
  x, which happens in the OOD and undersampling experiments.
- `tab_ood_autruth.tex` / `tab_undersampling_autruth.tex` / `tab_samplesize_autruth.tex`
  / `tab_noise_autruth.tex` — per region/knob: bias (`mean_x[AU(x) - sigma^2(x)]`,
  always computed, homoscedastic included), OLS slope/intercept of
  `AU(x) ~ sigma^2(x)` (slope shown; intercept computed but not tabulated — not
  requested as a column), and Pearson + Spearman correlation of `AU(x)` against
  `sigma^2(x)`, all across the region's grid points. **Homoscedastic cells (Lin-Hom,
  Sin-Hom) render slope/Pearson/Spearman as `---`** — `sigma^2(x)` is constant
  there, so the regression/correlation is undefined (zero-variance regressor), not
  zero or NaN. Detected by checking `var(sigma^2(x))` against a `1e-8` tolerance
  (`HOMOSCEDASTIC_VAR_TOL`), never by hardcoding which DGP names are homoscedastic.
  Bias is still reported in every homoscedastic cell.
- `tab_noise_au_sweep_corr.tex` — noise experiment only: correlates the 5 per-tau
  mean-AU values against tau itself, ACROSS the sweep rather than across x. Works
  in homoscedastic settings too, since tau varies even when `sigma^2(x)` does not.
  `---` when fewer than 3 tau values have data for that (DGP, model), or either
  series is constant over the available points (`MIN_SWEEP_POINTS_FOR_CORR = 3`).

**True noise variance `sigma^2(x)`** is not stored in any npz — reconstructed
analytically, verified directly against each experiment's actual
`generate_toy_regression` source (not assumed):
- OOD / Undersampling / Sample-size (fixed noise scale, matches `utils/mixture_metrics.py::DGP_TABLE`,
  itself verified earlier against `OOD.ipynb`/`"Sample Size.ipynb"`/`Undersampling.ipynb`):
  homoscedastic `sigma^2(x) = 1`; heteroscedastic `sigma^2(x) = 6.25 sin^2(0.5x+5)`.
- Noise-level (tau read from each file's own `tau` npz key, verified against
  `Experiments/Noise_Level.ipynb`'s `generate_toy_regression`): homoscedastic
  `sigma^2(x) = tau^2`; heteroscedastic `sigma^2(x) = tau^2 sin^2(0.5x+5)`.
  Consistent with the fixed-scale formula at tau=1 / tau=2.5.

**Number formatting** — shares, correlations and (normally) slopes are fixed to 3
decimals. Mean/sd and bias use a **per-column** choice between fixed-point and
scientific notation, decided from the realized value range (not hardcoded): fixed
if some precision in [4,6] decimals shows the column's smallest nonzero magnitude
as distinguishable from `0.0000` while keeping the largest value under `1e4`,
otherwise 3-significant-figure scientific notation
(`choose_column_format`/`fmt_meansd_cell`/`fmt_scalar_cell` in the script). This was
necessary, not cosmetic: real magnitudes span from ~1e-28 (near-degenerate
undersampling EU) to ~1e21 (BAMLSS's already-known OOD/heteroscedastic uncertainty
explosion — the same pathology `utils/plotting.py`'s `_reasonable_ood_ylim` clamps
in the OOD plots). **Slope gets the same treatment as mean/sd/bias, not fixed
3-decimals** — it is unbounded (unlike Pearson/Spearman, which are always in
[-1,1] by construction), and when AU explodes the OLS slope against a bounded
`sigma^2(x)` explodes with it; fixed-point rendered one BAMLSS cell as a 20+ digit
garbage string before this was caught and fixed. AU/EU mean and sd inside one
`$mean \pm sd$` cell always share the same format (can't mix fixed/scientific
within a `\pm`); the AU column and EU column are decided independently of each
other. The near-zero epistemic-share guard (`SHARE_DENOM_EPS = 1e-10`) excludes
points where `|AU(x)+EU(x)|` is negligible from the share mean — never silently:
the script prints the excluded-point count for every cell in its sanity-check
section (`--verify`-style stdout, not part of the `.tex` output).

## Captions

Each caption's closing sentence is generated from the actual computed numbers
(mean AU/EU delta between the two table regions, or between the first and last
swept knob value) — genuinely data-driven, not templated to match any expected
narrative. Wording is a first pass; edit freely.
